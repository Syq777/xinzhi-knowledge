# 分类规则与维护

## 三个独立维度

- **主题**：文章主要讲什么。沿用已有 15 个主题；根目录新文章按正文与标题信号推断，不移动文件。
- **方向**：横向＝综述、比较、趋势、多方案或清单；纵向＝聚焦一个对象、问题、机制或实践；横纵结合＝同时具有两类信号。横向并不等于浅，纵向并不等于深。
- **深度**：D0 信息不足；D1 信息或启发；D2 展开解释；D3 深度候选。不是来源可信度、事实正确性或阅读价值的评分。

## 自动初分的具体口径

扫描 `新枝/文章` 下所有以 🔗 开头的文章文件夹，只读取其中以 🔗 开头的 Markdown，排除个人批注。多份捕获按最长有效正文初评，保留全部原文链接。跨文件夹重复尚未合并。

方向首先依据标题的综述、比较、清单与实践、机制等信号，再参考既有主题；没有明确横向信号的完整文章暂归纵向。这是规则初分，不等于逐篇语义精读。边界不清的文章需要人工修订。

深度同时观察机制解释、具体案例、方法步骤、边界权衡、验证证据五组正文信号。每组至少命中 2 次才计为出现。D2 要求有效正文至少 900 字并有至少 3 组信号；D3 要求至少 2200 字、五组齐全，且边界和验证分别至少命中 3 次。长文不直接等于深度；关键词命中也不保证真实论证，因此 D3 始终叫“候选”。非技术散文和图片主导的文章可能被低估。

待核查目录或有效正文不足 300 字标为 D0，方向待判断。保留原有待核查状态，不将分类当作修复。

关键词来自固定词表，按标题、标题层级和正文命中加权，每篇最多 5 个。关键词页面连接相关原文卡，关系只是内容共现。未自动声称“支持、反驳、因果、前置知识”；这些需要精读证据才能添加。

## Obsidian 用法

打开 `00_知识全景`，进入 Canvas 或 Bases 表格。文章卡保存标题、主题、方向、深度、关键词、分类状态、原文等属性。标签适合过滤；指向主题页、关键词页的双向链接用于图谱。

文章原文保持原样；分类属性放在独立文章卡中。全局图谱搜索 `path:"新枝/知识全景"`，或从一个关键词页面查看两层局部图谱。总览 Canvas 按三个阅读领域展示全部主题；关键词共现 Canvas 展示跨主题关键词的前 10 个枢纽，每个最多连接共现数最多的 3 个主题，完整关系在关键词页中。

## 修订与增量更新

自动生成的卡片不直接编辑。编辑同目录 `分类修订.json`，示例：

```json
{
  "文章卡中的id": {
    "方向": "横纵结合",
    "深度": "D2-展开解释",
    "分类状态": "人工复核",
    "依据": "读完正文后的分类原因"
  }
}
```

然后从仓库根目录运行 `python3 tools/build-knowledge-map.py`。验证生成结果运行 `python3 tools/build-knowledge-map.py --check`。脚本不会删除遗留文件，原文移动或删除后应检查旧卡片；新增文章会纳入下一次生成。

本层目前保存在本地、受既有 Git 忽略规则保护，不改变公开发布范围。

格式参考：[Obsidian Bases](https://obsidian.md/help/bases/syntax) · [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/)。
