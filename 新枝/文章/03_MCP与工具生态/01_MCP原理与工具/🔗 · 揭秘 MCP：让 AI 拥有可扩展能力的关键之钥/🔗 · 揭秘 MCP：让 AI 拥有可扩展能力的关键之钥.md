【本期导读】大模型再强，也终究困在自身的知识边界里。要让AI从“会回答”走向“会行动”，它必须学会连接外部世界。Model Context Protocol（MCP）正是这把钥匙——让AI像人一样使用工具、访问系统、协作执行。它正在为AI开启真正的“可扩展时代”。

![图片](https://s.xinzhi-cdn.zone/user/66acedb068b6430eeafbea3d/6922892aa1fac977b4230f95/daf24767-5048-4a0b-a8cf-314ab37c3aa2.png)

在大模型的世界里，**能力边界**一直是个绕不开的话题。模型再强，也只能在「被训练过的知识」和「内置工具」范围内活动。当业务需求越来越复杂、垂直任务越来越多，我们就迫切需要一种方式，让模型**像人一样“学会使用工具”**，实现真正的能力扩展。这正是 **MCP（Model Context Protocol）** 登场的意义。本文将带你系统理解 MCP：它是什么、为什么出现、如何工作，展示它如何让大模型真正拥有“可扩展能力”，从一个“聪明的回答者”进化为一个“能动的执行者”。

MCP是什么

MCP（Model Context Protocol，模型上下文协议） 是一个 开源标准，用于让AI应用与外部系统无缝连接。通过MCP，像 Claude、ChatGPT这样的AI应用，不仅可以访问数据源（如本地文件、数据库），还可以使用工具（如搜索引擎、计算器）以及工作流（如专业化提示词）。

![图片](https://s.xinzhi-cdn.zone/user/66acedb068b6430eeafbea3d/6922892aa1fac977b4230f95/5e62c8b4-11f8-4bc4-a6ef-1630a3ecbabd.png)

这意味着AI不仅能“知道”，还真正能“去做”。你可以把 MCP 想象成 AI世界的 USB-C 接口：就像USB-C为电子设备提供了一种统一的连接方式，MCP 则为AI应用提供了一种标准化的方式，让它们能自由连接到各种外部系统和服务。

## 为什么需要 MCP

要理解MCP的意义，得先看看大型语言模型（LLM）的一个固有限制——它们只能依赖训练数据，无法访问训练之后的新信息或执行外部操作。这也就是我们常说的“知识截止”（knowledge cutoff）问题。

过去，AI界主要靠两种手段来突破这一限制：

1. RAG（检索增强生成）从外部资料库检索信息，再放入模型的上下文，让AI能利用最新资料回答问题。

2. 工具调用（Tool Use）给AI配备外部“工具”，例如计算器、天气查询接口、搜索引擎等，让它能主动行动。

但问题是——每个AI平台都需要为每个工具写独立的集成代码。这导致整个生态极度碎片化，工具无法通用、开发成本高、扩展性差。MCP 优雅地解决了这一问题。它把“工具”从具体AI实现中解耦出来，让任何支持MCP的AI都能直接调用任何支持MCP的工具。正如USB让所有设备都能即插即用，MCP让AI可以便捷的扩展工具。

## MCP 是如何工作的？

## MCP架构

MCP（模型上下文协议）采用的是一种典型的 **客户端—服务器（Client–Server）架构**。在这种架构下，一个 **MCP 主机（MCP Host）** —— 也就是像 **Claude Code** 或 **Claude Desktop** 这样的 AI 应用 —— 可以同时连接到一个或多个 **MCP 服务器（MCP Servers）**。主机在建立连接时，会为每个 MCP 服务器创建一个独立的 **MCP 客户端（MCP Client）**。每个客户端都与其对应的服务器保持一对一的专属连接，互不干扰。

![图片](https://s.xinzhi-cdn.zone/user/66acedb068b6430eeafbea3d/6922892aa1fac977b4230f95/048a6077-a9d6-417e-a5cb-f6526c8afdbe.png)

### 三个核心角色

- **MCP 主机（MCP Host）**👉 AI 应用本身，用于协调和管理多个 MCP 客户端。
- **MCP 客户端（MCP Client）**👉 负责与某个 MCP 服务器保持连接，并从该服务器获取上下文信息，供主机使用。
- **MCP 服务器（MCP Server）**👉 提供上下文或能力的服务端程序，响应客户端请求。


以 Claude Desktop 为例：

- Claude Desktop 扮演的是 **MCP 主机** 的角色。
- 当 Claude Desktop 连接到一个 MCP 服务器（比如 **Sentry MCP Server**）时，Claude Desktop 的运行时环境会创建一个 **MCP 客户端对象**，用于维持与该服务器的连接。
- 如果 Claude Desktop 再连接另一个 MCP 服务器（例如本地文件系统服务器），它就会再创建一个新的 MCP 客户端来维护新的连接。


![图片](https://s.xinzhi-cdn.zone/user/66acedb068b6430eeafbea3d/6922892aa1fac977b4230f95/84844129-367d-4325-a449-0bb10962733d.png)

因此，在 MCP 的架构中，**每个 MCP 客户端都与一个 MCP 服务器一一对应**，而主机（Host）则统一管理这些客户端，实现多源能力的协同。

## 图层

MCP 由两层组成：数据层和传输层

### 1️⃣ 数据层（Data Layer）

数据层是 MCP 的核心，基于 **JSON-RPC 2.0 协议** 构建，负责定义客户端与服务器之间的消息结构和语义。

它包括四大功能模块：

- **生命周期管理（Lifecycle Management）**处理客户端与服务器的连接初始化、能力协商，以及连接终止流程，确保通信顺畅可靠。
- **服务器特性（Server Features）**允许服务器提供核心功能，例如：
- **Tools（工具）**：可执行操作，如文件处理、API 调用、数据库查询**Resources（资源）**：提供上下文数据，如文件内容、数据库记录、API 响应**Prompts（提示模板）**：交互模板，用于指导模型生成行为
- **客户端特性（Client Features）**允许服务器向客户端请求：
- 调用宿主 LLM 进行内容生成获取用户输入记录日志信息
- **辅助特性（Utility Features）**支持实时通知和长任务进度跟踪等功能，使模型与外部系统的交互更灵活、更动态。


### 2️⃣ 传输层（Transport Layer）

传输层是 MCP 的「通信通道」，负责连接管理、消息封装和安全传输。它支持两种主要方式：

- **Stdio Transport**使用本地进程的标准输入输出流进行通信，性能高、无网络开销，**适合本地部署场景**。
- **Streamable HTTP Transport**使用 HTTP POST 发送客户端到服务器的消息，并可选用 **Server-Sent Events (SSE)** 实现流式通信。支持远程通信及多种认证方式，如 Bearer Token、API Key 或自定义 Header，官方推荐使用 **OAuth** 获取认证令牌。


> 传输层与数据层解耦——无论采用哪种通信方式，数据都统一使用 **JSON-RPC 2.0 格式**，保证了协议的通用性和扩展性。

## 数据层协议

### 生命周期管理

MCP 是 **有状态协议**，所以启动和关闭都需要管理流程。生命周期管理的主要作用是 **协商客户端和服务器各自支持的能力**，保证双方能顺利通信。

### 核心原语（Primitives）

原语是 MCP 的核心概念，决定了客户端和服务器可以互相做什么。

![图片](https://s.xinzhi-cdn.zone/user/66acedb068b6430eeafbea3d/6922892aa1fac977b4230f95/53de6b21-0bf8-4816-a59a-08932757c84a.png)

#### 服务器端原语

服务器可以提供三类原语：

1. **工具（Tools）**：可执行函数，比如文件操作、API 调用或数据库查询。
2. **资源（Resources）**：提供上下文信息的数据源，比如文件内容、数据库记录或 API 返回的数据。
3. **提示（Prompts）**：可复用的交互模板，比如系统提示或少量示例（few-shot examples）。


原语言说明示例控制方工具（Tools）LLM 可以主动调用的功能，并决定何时使用。工具可以写入数据库、调用外部 API、修改文件或触发其他逻辑。搜索航班、发送消息、创建日历事件模型资源（Resources）提供只读访问的被动数据源，用于提供上下文信息，例如文件内容、数据库结构或 API 文档。检索文档、访问知识库、读取日历应用程序提示（Prompts）预构建的指令模板，告诉模型如何使用特定工具和资源。安排假期、总结会议、起草邮件用户

操作方式：

- **列出（list）**：查看有哪些原语可用
- **获取（get）**：获取具体内容
- **执行（call，针对工具）**：运行功能


**示例**：一个提供数据库服务的 MCP 服务器可以：

- 提供查询数据库的工具；
- 提供数据库模式信息的资源；
- 提供带少量示例的提示模板，让客户端更智能地使用工具。


#### 客户端原语

#### 客户端也可以提供原语，让服务器调用：

1. **采样（Sampling）**：请求客户端生成语言模型输出，不需要在服务器端集成模型 SDK。
2. **引导（Elicitation）**：向用户收集更多信息或确认操作。
3. **日志（Logging）**：发送调试或监控日志给客户端。


### 实时通知

MCP 支持实时通知，让客户端随时获得服务器更新。例如：

- 当服务器新增工具，或修改现有工具时，会发送通知给客户端。
- 通知使用 JSON-RPC 2.0 的 notification 消息，不需要客户端回复。


💡 **总结**：

- MCP 数据层就是客户端和服务器“说话”的规则和工具。
- 服务器提供工具、资源、提示；客户端提供采样、引导和日志。
- 生命周期管理保证双方能力匹配，通知机制保证信息实时更新。
