这些问题的核心在于：Prompt Engineering、Context Engineering 和 Harness Engineering 分别解决了什么问题？它们的目标又是什么？

1. Prompt Engineering  
    在最开始的阶段，我们主要依靠 Prompt Engineering。通过一些技巧（比如零样本、少样本、正例、反例）以及思维链（CoT）、角色扮演（Role Play）和提示链（类似于将任务拆分为子任务）来引导模型。
    
2. Context Engineering  
    随着大模型理解意图的能力越来越强，即便表达不够精准，模型也能理解，因此纯写 Prompt 的边际效应开始降低，进而衍生出了 Context Engineering。  
    模型有了记忆和上下文，我们需要对其进行控制。在这个过程中，衍生出了以下几种技术：  
    (a) RAG：相当于将检索到的索引内容作为外部知识库，传入模型的上下文中。  
    (b) 上下文压缩：随着对话变长，模型会出现“遗忘”现象。根据研究，模型存在 Loss in the Middle（中间遗忘）的过程。  
    © 解决方案：采用上下文压缩技术，例如滚动摘要、重要性评分或层次记忆。  
    这样做是为了确保 AI 信息来源的唯一性、可管控性和可追溯性，所以我们需要对上下文保持高度关注。
    
3. Harness Engineering  
    即便写了很多 Prompt 和上下文，依然缺乏约束和验证反馈机制。Harness Engineering 此时脱颖而出，它的核心理念是：除了模型本身之外，所有运行时的东西都属于 Harness。  
    Harness 主要涉及：  
    (a) 上下文治理  
    (b) 验证闭环  
    © 角色分工机制（作为对模型的一种限制）
    

这三者之间是包含关系，而不是替代关系。然而，模型越优秀，所需的 Harness 可能就越简单。因此，目前的 Harness Engine 并非最终的版本答案，而是一个过渡性的技术。未来的规则应当是自动化的，而不是……
