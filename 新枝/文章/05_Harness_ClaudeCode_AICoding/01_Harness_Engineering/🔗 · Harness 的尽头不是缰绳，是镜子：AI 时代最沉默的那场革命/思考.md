这篇文章讨论了 Harness 出现的原因及其所处的环境。

本质上，Harness 的出现是为了将“隐性知识”显性化。其核心逻辑在于，只有让系统“看见”之前看不见的部分，才能对其进行统一的组织和度量，就像历史上“统一度量衡”一样。

该体系结构主要分为三层：

1. 意图层 (Intent Layer)  
    我们要为所做的事情下达明确、显性且可执行的定义。定义的粒度越细、越清楚，后续反工的概率就越小。  
    这一层在命名上比较多样，可以叫 Spec-Driven、SDD (Spec-Driven Development)、PRD as Code 或者 Plan-First。其核心是将“要做什么”拆解为详细的过程，让 AI 能够理解。  
    换句话说，如果你无法写清楚文档，说明你还没想明白；在没有清晰思路的情况下盲目去做，反工的概率极高。
    
2. 执行层 (Execution Layer)  
    过去，大家认为执行环节包含很多“隐性知识”。比如程序员虽然喜欢 Coding，但写代码在整个软件工程中其实只是很小的一个环节。  
    现在的区别在于，我们需要把做事的方法论转化为 AI 可理解的、可版本化的流程。具体包括：  
    (a) 读取需求、列出草稿、查询历史  
    (b) 写一段、跑一段，然后自我审计  
    © 进行测试并发送 MR  
    你必须让 AI 明确什么是成功，以及成功后的标准样貌。
    
3. 判断层 (Judgment Layer / Evaluation)  
    这一层负责最终验收、失败模式分析和对抗检查。  
    目前的挑战在于 LLM 存在“自我一致性偏见” (Self-consistency Bias)，即同一个模型往往会认为自己生成的内容是对的。因此，必须引入另一个模型进行对抗性评估（如使用 Meta 的 Llama、Anthropic 的 Claude Opus 或 Typeless 列出的标准和代码进行交叉验证）。
    

这篇文章用了一些偏哲学的思路来解释 Agent 工程化的问题，确实很有深度，虽然有些地方还没完全读透，但感觉很有启发。
